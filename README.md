# MGPU Bridge 帧生成闪烁横条修复

[English](README.en.md)

这是 [MGPU Bridge](https://github.com/maohgad-web/Neural-coprocessor) 的一个补丁，基于 [davidm71 的分支](https://github.com/davidm71/Neural-coprocessor)（commit `c40734d`，source `DG3`）。已向原分支提交 [PR #1](https://github.com/davidm71/Neural-coprocessor/pull/1)。它解决两类问题：

- 开启帧生成后，游戏在前台时画面上出现**闪烁的黑色横条**，插件面板也会横向闪烁。
- 插件面板的小光标有时**动不了**，关闭面板后还会**留在屏幕上**。

## 现象

- 只有游戏在前台时才出现。把焦点切到另一个屏幕，即使画面没有被任何窗口遮挡，横条也会立刻消失。
- 不移动镜头也有，与画面运动无关。
- 截图里看不到。
- 帧生成倍率越高越明显。

## 原因

`present_frame` 每一帧都按这个顺序写同一个后台缓冲：先清屏成深灰色，再把画面拷贝上去，然后画 HUD，最后由 ReShade 在 `Present` 内部画面板。

这条交换链只有 **2 个缓冲**。游戏在前台时，它运行在 `Hardware: Independent Flip`、允许撕裂的模式下，相邻两次翻转最短只隔约 0.3 ms。这时屏幕读到了还在写入的缓冲，写到哪一步，横条里就显示哪一步：

| 屏幕读到时写到的阶段 | 看到的现象 |
|---|---|
| 刚清屏 | 黑色横条 |
| 拷贝完、面板还没画 | 面板区域出现游戏图案的横条 |

截图看不到，是因为截图是在拷贝完成之后才读取缓冲。

### 证据

1. **染色：** 把清屏色改成洋红，横条就变成洋红。
2. **去除：** 去掉这次清屏，2X 和 4X 下的黑条都消失了，但面板区域的闪烁还在，说明清屏只是问题的一个可见阶段。
3. **加缓冲：** 打开探针（每帧都清成洋红）后逐级增加缓冲：

| 缓冲数 | 2X | 4X |
|---|---|---|
| 2 | 持续有洋红条，面板也闪 | 未单独记录 |
| 3 | 只在打开面板时闪过 1 帧 | 少量闪烁 |
| 4 | 干净 | 少量闪烁 |
| **6** | **干净，面板也不闪** | **干净** |

## 修复内容

- **按需清屏：** 只有画面盖不满后台缓冲时才清屏，所以每帧不再有那个深灰色的阶段。这一步消除了黑条。
- **`PresentBuffers`：** 缓冲数可设为 2–6，默认 6。可以在面板里调，重启游戏后生效。这一步消除了面板闪烁。
- **`PresentRaceProbe=1`：** 保留洋红探针作为诊断工具，不需要单独编译。
- **缩放器：** 描述符改成每个缓冲一组，避免与更多缓冲冲突。
- **面板光标留在屏幕上：** 关闭面板时没有人把 `MouseDrawCursor` 复位，现在会复位。
- **面板光标动不了：** 原来只要鼠标钩子收到过一个事件，这次打开期间就一直用它，而这个游戏里钩子几乎收不到事件。现在改为哪个来源最后动过就用哪个。8 次打开面板的日志里，有 3 次卡住的都是这个原因。

### 对延迟的影响

下面是从提交画面到上屏的时间。缓冲增加后没有变长。

| 缓冲数 | 前台帧数 | p50 | p99 |
|---|---|---|---|
| 2 | 约 9,400 | 0.50 ms | 2.66 ms |
| 4 | 约 600 | 0.37 ms | 2.45 ms |
| 6 | 约 30,800 | 0.39 ms | 2.42 ms |

这组数据都是在 `PresentLatency1=1` 下测的，只覆盖提交到上屏这一段，不是完整的鼠标到屏幕延迟。

## 安装

需要已经装好可用的 MGPU Bridge（davidm71 的 DG3 版）。

下载：[MGPU_Bridge_BB1.zip](release/MGPU_Bridge_BB1.zip)（SHA-256：`347633912b3c691442c3bc57b51a1197d8b95cd9af3f843b9020b0fbefd0f542`）

1. 完全退出游戏。
2. 备份游戏目录（`dxgi.dll` 旁边）里的 `nvngx.dll_mgpu_bridge.addon64`。
3. 用发布包里的同名文件覆盖它。
4. **不要覆盖你的 `mgpu.ini`。** 不加任何配置就默认使用 6 个缓冲。
5. 进游戏后查看 `ReShade.log`，应该能看到 `source BB1` 和 `present chain created ... buffers=6`。

要回退，把备份改回原名即可。

## 测试范围

这个修复只在一套环境上测试过，**其他显卡、游戏和设置都没有验证**：

- 2 × RTX 5080（一张渲染，一张跑 DLSS），驱动 621.01
- 《剑星》，4K 120 Hz，`DcompOverlay=1`，`Scaler=0`，帧生成 2X 和 4X

## 尚未确认的部分

- **屏幕为什么会读到还在写入的缓冲。** 上面的解释最符合目前的证据，但确切机制没有证实。所需缓冲数随帧生成倍率上升，这符合“翻转排在屏幕前面”的推断，也只是推断。
- **前台为什么不等垂直同步。** 代码调用的是 `Present(1, 0)`，PresentMon 在前台却报告 `SyncInterval=0`。
- **低延迟呈现关闭时的延迟。** `PresentLatency1=0` 加 6 缓冲时，画面已确认干净，但延迟没有测到。原版 2 缓冲在这个设置下，后台路径的 p50 已经有 12–24 ms。
- **缩放器路径。** 只做过代码检查，没有实际运行。

4X 下画面偏块状（“豆腐块”）不在这个修复的范围内，测试者认为这来自 DLSS 帧生成本身，但这一点没有验证。

## 从源码构建

```bash
git clone https://github.com/davidm71/Neural-coprocessor
cd Neural-coprocessor
git checkout c40734d
git am --keep-cr patches/bb1-on-davidm71-c40734d.patch
```

依赖的获取方式见该仓库的 `.github/workflows/build.yml`（把 ReShade 和 NVIDIA DLSS 的头文件放进 `ext/`），然后用 VS 2022 配合 CMake 编译。发布包是用 MSVC 14.44、Ninja、Release 配置构建的，没有经过该仓库的 CI。

该仓库的 CI 现在过不了它自己的检查：`src/gputime.cpp:217` 使用了被检查拦截的 `GetClockCalibration`。这个问题与本补丁无关。
